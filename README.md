# chat_agent：QQ／微信聊天机器人

基于 Hermes Agent 的轻量聊天项目，运行在共享 Ubuntu 服务器上。模型推理使用远程 API，会话保存在 SQLite，长期记忆按用户隔离。本仓库保存部署文档、补丁和辅助脚本；Hermes 主程序位于服务器。

## 当前状态

2026-10-08 核验：Hermes 固定为 v0.21.5，QQ／微信均连接单个网关。主模型为 `cn:deepseek-v4-flash`，通过 `https://wb.yinxingye.space/v1` 中转，备用为 `kldai/gpt-6-sol`。用户隔离、受限提醒及轻量主动关心已部署。

微信已接入同一个网关，仅允许授权账号私聊，真实收发、多轮上下文和平台身份隔离已验证。QQ／微信共用小云人格，各自的记忆、历史和提醒分开。微信群聊未开放；STT 已关闭；Vision、TTS、媒体清理、限流和 systemd 自动恢复尚未完成验收。当前运行单个手动网关，不能视为完整的 24×7 多模态部署。

## 数据边界

用户以 `(平台, user_id)` 区分，QQ 与微信不合并身份。

| 场景 | 长期记忆 | 历史检索 |
| --- | --- | --- |
| 私聊 | 该用户的私聊记忆 | 同平台该用户的私聊和群聊记录 |
| 群聊 | 该用户所有群共用的群记忆 | 该用户在当前群的记录 |

私聊可按用户要求只读获取群记忆；群聊不能读取私聊记忆。身份无法核实时拒绝记忆和检索访问。

QQ 和微信当前仅向白名单开放。不得直接运行 `hermes update`，不得重复执行首次部署脚本；维护前阅读部署记录并保留现有 QQ 群回复补丁。

QQ／微信均已增加受限的私聊一次性提醒：可说“2 分钟后提醒我喝水”“查看我的提醒”“取消某条提醒”。提醒只发送给当前平台的本人，最长 30 天；依赖网关持续运行，实际投递受平台权限和会话有效期约束。群提醒和循环提醒暂未开放。

新建提醒时，小云会按人格写好到点发送的文案；需要保留原话时说明“届时原样发送”。触发时发送已保存文字，已有任务不自动改写。

## 主动关心与生日

独立 `social.db` 保存简短事项，不复制完整聊天。仅本人私聊可用，QQ／微信分别管理。

- 当前两个授权账号已开启主动关心，新账号需先同意。小云可从正常聊天记录具体未来事件或未聊完的日常话题；敏感话题、第三方事件和模糊愿望不纳入。
- 新私聊后必须复核旧事项，未复核则暂停发送。每用户最多 5 个候选、每 48 小时最多一次关心；23:00–08:00 免打扰，近期两小时内聊天会延后。不回应不追发。
- 可说“查看待跟进事项”“这件事已经结束”“不要主动关心我”“重新开启主动关心”。明确提醒仍用原有提醒工具。
- 生日须明确订阅，例如“我的生日是公历 5 月 20 日，每年早上 9 点祝福我，我确认订阅”。只存月日，默认北京时间 09:00，可选 08:00–22:59；2 月 29 日非闰年按 3 月 1 日。
- 可说“查看生日订阅”“取消这条生日订阅”。关闭主动关心不影响生日或已有明确提醒。

普通聊天静默保存候选、自然接话，不播报“记好了”或预告问候时间；复核和新增合为一次工具调用。用户主动查询、设置生日或明确提醒时才给管理确认。

发送时不调用模型，使用提前写好的人格文字。投递不确定时不自动重发；网关停机、平台权限或微信会话失效可能影响到达。208 项隔离与回归通过，两平台自动候选及测试生日真实投递已验证；静默回复已实测，两平台各一次批量维护，本轮约 13.9／10.1 秒；测试记录已清理。普通关心在实际日期到点后的持续表现仍待观察。
